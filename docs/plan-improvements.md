## P0 — Сейчас (8–16 августа)

### P0.1 Автодеплой сайта из CI (4–6 ч)
- GitHub Actions workflow `deploy.yml`: на push в main, если изменились
  `data/*.csv` или `apps/web/**` → `vercel --prod --token=${{ secrets.VERCEL_TOKEN }}`
- Секрет `VERCEL_TOKEN`: `vercel login` → `vercel token create` (или `vercel
  auth token`), добавить в GitHub Secrets
- Результат: прогон данных → коммит CSV → сайт обновился автоматически
- Зависимость: нет; разблокирует остальные P1-пункты сайта

### P0.2 Прогон B (9 августа, по датам) — 1 ч
- Все ингейшены (ИТМО + 10 вузов) после приказов 2-й волны ИТМО
- Снять приказ ИТМО 2-й волны → метки (дополнить orders_itmo_2026.csv)
- Обновить `data/aggregates_2026.csv` → коммит → автодеплой

### P0.3 Прогон C (11–12 августа, по датам) — 1 ч
- Финальные snapshot'ы (после приказов МГУ); проверка ВШЭ (вдруг выгрузки появились)
- Экспорт агрегатов, коммит

### P0.4 Калибровка v0 (13–16 августа) — 2 дня
- Прогнозы на snapshot'ах прогона B (последние до приказов) при
  `POSTUPI_FORECASTING_ENABLED=true`
- HMAC-метки ИТМО (готово: `orders_itmo_2026_hmac.csv`) + метки МГУ из
  статусов → decile calibration curve, Brier
- Отчёт `docs/calibration-v0.md` + гипотезы для модели v1
- Зависимость: P0.2, P0.3

## P1 — Август–сентябрь

### P1.1 Публичный JSON API на сайте (3–4 ч)
- `apps/web/main.py`: `GET /data/aggregates.json` (группы + проходные, без
  кодов/HMAC) + `GET /api/universities`, `GET /api/groups?university=`
- Тесты страниц; используется калькулятором позже
- Зависимость: нет

### P1.2 Страница «Как считаем» (3–4 ч)
- `apps/web/templates/method.html`: как собираются данные, что такое
  проходной (мин. балл зачисленных по общему конкурсу без БВИ), ограничения
  (прогноз ≠ гарантия), ссылка на модель на GitHub
- Ссылка в футере/главной

### P1.3 Бот: исправить help_text + дата snapshot в карточке (1–2 ч)
- `apps/bot/presenters.py`: убрать «уведомлений нет», добавить вузы
- `apps/bot/service.py`: показать дату последнего snapshot в track_detail

### P1.4 Названия групп МЭИ и Сеченовки (4–6 ч)
- МЭИ: discovery-страницы направлений (mpei.ru/priem) → маппинг
  `list*.html` ↔ название направления
- Сеченовка: названия из `select` на странице-индексе (`admission-lists/`)
  — связать `COMPETITIVE_GROUP_ID` ↔ название специальности
- Перепрогон вузов, обновление агрегатов

### P1.5 КЦП-фетчер (места для всех вузов) (1–2 дня)
- Единый источник мест: парсинг страниц «Количество мест» приёмных комиссий
  (МИСИС/МЭИ/Станкин/РУДН/Сеченовка/ФинУнивер/Губкин) или КЦП Минобрнауки
- Сохранять в `seat_counts` (уже в контракте); прогнозный гейт для вузов с местами
- Зависимость: нет; разблокирует прогноз для новых вузов

### P1.6 Поиск группы в боте (4–6 ч)
- `/find <текст>`: поиск по названию группы во внутреннем API
  (`/internal/competition-groups?q=`) + выбор из результатов → добавление трека
- Зависимость: P1.3 (общий онбординг)

### P1.7 Проходные по годам (1–2 дня)
- Собрать архивы: МГУ (страницы проходных 2011–2025 на msu.ru),
  МИРЭА (selection/2013–2025), РГГУ (scores.php)
- `data/passing_by_year.csv` (вуз, направление, год, проходной) + страница
  направления с динамикой (спарклайн)
- Зависимость: P1.1 (формат данных)

### P1.8 Smoke-тест источников (3–4 ч)
- Скрипт `apps/tools/smoke_sources.py`: HEAD/GET всех URL из реестра,
  проверка статусов + минимальной валидности ответа
- CI-джоба daily (cron) + локальный запуск
- Зависимость: нет

### P1.9 ВШЭ: XLSX-адаптер (1–2 дня, после появления выгрузок)
- Мониторить `enrol.hse.ru/storage/public_report_2026/`; когда файлы появятся
  (как 2025) — парсер XLSX по образцу 2025 + fresh discovery для групп
- Зависимость: появление выгрузок (после кампании)

# Детальный план: август 2026 → июнь 2027

Итоговый план подготовки к приёмной кампании 2027. Обзорные фазы — в
[ROADMAP.md](../ROADMAP.md); этот файл — рабочий план с датами и
deliverable.

## Контекст и допущения

- Старт: суббота 8 августа 2026. Кампания 2026 ещё идёт (приказы 2-й волны
  ~9–11 августа) — первые дни плана срочные.
- Один основной разработчик, ~10–15 часов в неделю. Буфер: 3 недели
  запасных за весь период (заложены в феврале и мае 2027).
- Реальные события кампании 2027 (по аналогии с 2026):
  - ЕГЭ основной период: 26 мая – 20 июня 2027.
  - Подача документов: 20 июня – 25 июля 2027.
  - Публикация конкурсных списков: с 27 июля 2027.
  - Приказы о зачислении: ~4 и ~9 августа 2027.
- Ключевой ресурс — архив 2026: без финальных списков и меток зачисления
  невозможна калибровка прогноза. Это приоритет №1.
- Рабочая неделя: пн–пт вечера + выходные. Deliverable каждой недели —
  проверяемый результат (запущенные проверки, тесты, публикация).

## Неделя 0 — Архив 2026: успеть до приказов (8–16 августа)

Цель недели: не потерять данные кампании 2026.

- **8 авг (сб):** развернуть проект локально (venv, `.env`, docker compose,
  `alembic upgrade head`); прогнать `make check`; зафиксировать, что падает.
- **9 авг (вс):** снять финальные snapshot'ы ИТМО (весь batch) и ВШЭ —
  последний день, когда списки отражают реальный конкурс до приказов.
  Сохранить приказы о зачислении 1-й волны (от ~4 авг), если ещё доступны.
- **10 авг (пн):** снять приказ 2-й волны ИТМО (списки зачисленных) —
  это и есть метки «прошёл/не прошёл» для калибровки. Сверить с финальными
  списками: кого зачислили, кто ушёл.
- **11 авг (вт):** то же для ВШЭ (если публикует приказы); иначе — собрать
  финальные списки + статусы согласий.
- **12 авг (ср):** нормализовать архив: экспорт snapshot'ов 2026 и меток
  зачисления в приватные фикстуры (`fixtures/private/`, `.local-fixtures/` —
  уже в .gitignore). Никаких ФИО в Git.
- **13 авг (чт):** агрегаты 2026: проходные баллы по группам ИТМО/ВШЭ —
  фундамент сайта-витрины и калькулятора.
- **14 авг (пт):** CI на GitHub Actions: `pytest + ruff + mypy` на каждый PR.
- **15–16 авг (сб–вс):** шаблоны Issues (баг, фича, «добавить вуз»,
  «источник изменился»); чек-лист «что сломалось за кампанию 2026» по
  git log и известным проблемам.

**Результат недели:** полный приватный архив 2026 (списки + метки), CI
работает, Issues-шаблоны опубликованы.

## Риски и контриеры

| Риск | Контриера |
|---|---|
| Архив 2026 потерян (приказы недоступны) | Снять всё до 11 августа; калибровка по «финальный список vs последний список» без приказов — запасной вариант |
| Вуз закрывает/усложняет списки | Замена из очереди аудита; каждому вузу — запасной кандидат |
| Парсеры ломаются в разгар сезона | Ежедневный smoke-тест источников + runbook + алерт мейнтейнеру |
| Не хватает времени (один разработчик) | 3 резервные недели; жёсткий приоритет: парсеры > калибровка > сайт > бот-полировка |
| Сайт-витрина отстаёт | Калькулятор и страницы — только агрегаты из уже готовых данных; никакого кабинета |
| Юридические вопросы (152-ФЗ) | Публикуем только агрегаты; сырые списки и ФИО — только в приватных фикстурах |

## Правило недели

Одна неделя — один фокус. Если задача недели не закрыта — она переносится
в fix-недели (15, 24, 32, 35), а не размазывается по следующей. В конце
каждой недели — короткий чек-ин в Issues (или changelog), чтобы план не
расходился с реальностью.

# План интеграции вузов (по итогам разведки 08.08.2026)

Цель: подключить к кампании 2027 все вузы с подтверждёнными открытыми
источниками. Существующая инфраструктура уже универсальна: `persist_snapshot`,
diff, уведомления, бот и модели БД не зависят от конкретного вуза. Меняются
только парсеры, фетчеры и конфигурация.

## Архитектурные изменения (минимальные, обратно совместимые)

### 1. Реестр парсеров — новый `packages/parsers/registry.py`

```python
@dataclass(frozen=True)
class UniversitySource:
    code: str            # "msu", "mephi", ...
    name: str
    parser: type[BaseUniversityParser]
    fetcher: Callable[..., Awaitable[FetchedDocument]]  # GET/PDF/JSON
    forecast_eligible: bool = False   # включается после валидации
    enabled: bool = True

SOURCES: dict[str, UniversitySource] = { ... }
```

Парсеры остаются `BaseUniversityParser.parse(content, source_url, fetched_at)`
— контракт не меняется. У каждого вуза свой модуль `packages/parsers/<code>.py`
+ свой fetcher (обычный GET, GET с Referer, JSON-API, PDF-скачивание).

### 2. Конфигурация — `packages/common/config.py`

- `POSTUPI_ACTIVE_UNIVERSITIES` (по умолчанию `itmo,hse,mipt`) — какие
  источники включены; пусто = все из реестра.
- Остальные настройки не меняются.

### 3. Общий ингейшн — новый `apps/worker/universal_ingestion.py`

- Цикл по активным источникам: fetch → parse → `persist_snapshot` →
  вернуть `IngestionOutcome` (как `itmo_ingestion`).
- `apps/worker/jobs.py`: `ingest_universities_job` (почасовой cron) —
  замена `enqueue_itmo_refresh`; ИТМО продолжает работать через тот же
  механизм (batch-семантика ИТМО сохраняется в его фетчере).
- Частоту для отдельных вузов можно задать в `UniversitySource.refresh_minutes`
  (медленные источники — реже).

### 4. Прогнозный гейт — `packages/forecasting/recompute.py`

- Заменить `university.code != "itmo"` на `not SOURCES[code].forecast_eligible`.
- `forecast_eligible=True` выставляется только после валидации по чек-листу
  (см. ниже): полный batch, verified приоритеты, места, ≥3 snapshot.
- Стартовый состав eligible: ИТМО (+ ВШЭ при появлении мест). Новые вузы
  подключаются к прогнозу по одному, после накопления истории.

### 5. Места (seat_counts) — уже в контракте

`NormalizedCompetitionGroup.seat_counts[condition]` уже существует — каждый
парсер заполняет его из своего источника (МГУ: «Всего мест: N»; Станкин:
«Количество мест на выбранный конкурс»; РНИМУ: plan из JSON; ФинУнивер:
колонка «Кол-во бюдж. мест»; МЭИ/МИСИС/РУДН: из страниц групп). Для вузов
без мест в списках — отдельный КЦП-фетчер (приоритет — потом).

### 6. Что НЕ меняется

Модели БД, `persist_snapshot`, diff (`snapshot-diff-1`), политика
уведомлений, приватность (HMAC + DiscardingRawSnapshotStorage), бот
(группы подтянутся из БД автоматически), миграции не нужны.

## Шаблон подключения вуза (чек-лист, ~1–1.5 недели)

1. **Аудит-факты**: URL списков, формат, поля, анонимизация (код/ФИО),
   обновление (дата на странице), места. → в `docs/universities.md`.
2. **Фикстура**: приватный снапшот в `fixtures/private/<code>/` (без ФИО
   в Git) — по образцу ITMO 2199.
3. **Парсер** `packages/parsers/<code>.py`: разбор → `ParsedSnapshot`;
   identity_namespace = `admissions_uid:<code>:<campaign>`.
4. **Фетчер**: загрузка списка групп + каждого списка (пагинация, Referer,
   API-эндпоинты).
5. **Unit-тесты** на фикстурах + **интеграционный тест** `persist_snapshot`.
6. **Регистрация** в `registry.py` (forecast_eligible=False) + в
   `POSTUPI_ACTIVE_UNIVERSITIES`.
7. **Прогон** `ingest_universities_job` на staging; сверка количества строк
   с источником.
8. **Валидация прогноза** (для eligible): полный batch, приоритеты,
   места, 3+ snapshot → включить прогноз.
9. **Smoke-тест источников**: еженедельный прогон всех парсеров на живых
   страницах (вне сезона — по архивам/прошлым годам).
10. Документация: статус в `docs/universities.md`, changelog.

## Риски

| Риск | Контриера |
|---|---|
| PDF Бауманки содержит ФИО/СНИЛС | Проверить при фикстуре; если ФИО — только агрегаты (витрина), трекер отложить |
| МГИМО XLS не скачивается без cookie | Разбор через браузер-фетчер (playwright) или отказаться (волна 2) |
| МГУ: 39 факультетов × много групп = большой batch | Сегментированный batch по факультетам; частота — реже |
| Источники меняют структуру в сезон 2027 | Еженедельный smoke-тест + runbook + алерты |
| Места (seat_counts) у части вузов нет в списках | КЦП-фетчер; прогноз для таких вузов — после появления мест |
| Время (один разработчик) | Жёсткий приоритет: волна 1 > волна 2; лёгкие SSR — первыми |
